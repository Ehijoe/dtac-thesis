% Background
\section{Background to the Study}

Web caches are fundamental infrastructure systems designed to reduce web server load and latency by storing resources geographically and network-wise closer to the user~\cite{breslau1999web}.
By serving repeated requests from intermediate storage, caching prevents the need to fetch content directly from the origin web server on every individual request~\cite{breslau1999web, umar2026experimental}.
Historically, web caching algorithms have been highly effective because human browsing patterns naturally follow the Zipfian law, where a small set of popular web pages are requested frequently while the vast majority are accessed rarely~\cite{breslau1999web}.
This strong human locality of reference established the foundation for traditional caching eviction policies such as the Least Recently Used (LRU) algorithm~\cite{breslau1999web}.

However, the modern web ecosystem has experienced a massive influx of Artificial Intelligence (AI) scrapers and automated crawlers designed to harvest vast quantities of web data for training machine learning models~\cite{zhang2025rethinking}.
Unlike human users, these AI scrapers typically make high-volume, singular, and non-recurring requests across wide swaths of web pages that will never be requested again~\cite{zhang2025rethinking}.
This behavior fundamentally breaks the Zipfian distribution pattern that traditional caching algorithms rely upon~\cite{breslau1999web, zhang2025rethinking}.
Furthermore, recent empirical studies demonstrate that modern AI scrapers selectively ignore standard domain directives such as \texttt{robots.txt}, rendering passive exclusion policies ineffective~\cite{kim2025scrapers}.
Consequently, current caching algorithms fail to handle this uniform, non-recurring traffic effectively, leading to severe operational inefficiencies~\cite{zhang2025rethinking}.

% Statement of Problem
\section{Statement of the Problem}
High-volume, non-recurring requests generated by AI scrapers induce severe cache pollution across intermediate routing nodes~\cite{zhang2025rethinking}.
When automated bots flood a server with one-off requests for training data, traditional eviction algorithms such as LRU treat these new items with equal temporal importance to legitimate user traffic~\cite{breslau1999web, zhang2025rethinking}.
This forces caching systems to prematurely evict frequently accessed human content to make space for scraper artifacts that will never be retrieved again~\cite{zhang2025rethinking}.
This phenomenon results in critical infrastructure failures such as cache thrashing, ultimately degrading overall system performance, inflating origin server loads, and increasing latency for legitimate human users~\cite{zhang2025rethinking}.

% Objectives
\section{Objectives of the Research}
The primary aim of this research is to implement dynamic, heuristic caching to mitigate AI scraper interference and preserve web cache efficiency~\cite{zhang2025rethinking}.
To achieve this aim, the specific objectives of the research are to:
\begin{enumerate}
    \item Build a lightweight heuristic detector utilizing the ``Shy Guys'' passive detection approach based on favicon and HTTP header anomalies~\cite{vanboxem2026shy}.
    \item Assign a real-time ``AI-score'' ranging continuously from $0.0$ to $1.0$ to every incoming HTTP request to quantify the probability of automated scraper origin~\cite{vanboxem2026shy}.
    \item Create a Dynamic Traffic-Aware Cache (DTAC) architecture that actively modifies Least Recently Used (LRU) eviction algorithms based on the assigned real-time AI-scores~\cite{zhang2025rethinking}.
    \item Evaluate the DTAC prototype by comparing its cache hit rates against standard LRU baseline performance under controlled, mixed traffic conditions~\cite{breslau1999web, zhang2025rethinking}.
\end{enumerate}

% Scope
\section{Scope of the Research}
This study focuses on server-side web caching infrastructure and routing optimization in the presence of automated scraping workloads~\cite{umar2026experimental, zhang2025rethinking}.
Architecturally, the research is bounded by the design and implementation of a two-stage system comprising a Heuristic Proxy---featuring a State Manager and an AI-Score Generator---and a DTAC AI-aware LRU Cache positioned upstream of an origin web server~\cite{vanboxem2026shy, zhang2025rethinking}.

Methodologically, the scope is divided into two phases: a System Development Sandbox dedicated to functional acceptance testing, proxy stability, and algorithm debugging without system crashes; and a Controlled Testing and Benchmarking Track~\cite{umar2026experimental}.
The evaluation is strictly confined to simulated workloads combining Zipf-distributed human traffic and uniformly distributed AI scraper requests, benchmarking the proposed DTAC prototype directly against standard state-of-the-art LRU eviction metrics~\cite{breslau1999web, zhang2025rethinking}.

% Justification
\section{Justification for the Research}
The exponential growth of large language models and AI tools has driven a corresponding surge in web scraping activity~\cite{zhang2025rethinking}.
Because empirical evidence confirms that AI scrapers routinely ignore voluntary compliance mechanisms like \texttt{robots.txt}, web administrators can no longer rely on protocol-based exclusion to protect their infrastructure~\cite{kim2025scrapers}.
While network-level defenses such as hierarchical IP hashing exist to mitigate high-volume scraper strain, server-side caching systems themselves must be architecturally modernized to survive modern traffic anomalies~\cite{hoetzlein2025protecting, umar2026experimental}.

This research is justified by its direct utility in safeguarding web performance~\cite{umar2026experimental}.
By introducing an AI-aware heuristic eviction mechanism, the proposed DTAC system protects human traffic by preserving the temporal locality benefits of caching for actual end users~\cite{breslau1999web, zhang2025rethinking}.
Successful implementation will significantly improve infrastructure efficiency, achieving substantially higher cache hit rates for human traffic during periods of heavy scraper congestion compared to traditional LRU algorithms, thereby saving server compute, bandwidth, and operational costs~\cite{breslau1999web, zhang2025rethinking}.
